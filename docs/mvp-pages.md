# MVP 页面与交互规格（讨论稿 v0.2）

依据：[requirements.md](requirements.md) v0.5 的讨论结论
范围：单用户、多项目、项目内按版本排期；需求层级/拆分、版本历史、沟通、变更、附件、实际开发日期；验收和正式交付暂不做。

> 2026-10-21 调整：原“客户”实体、页面和项目字段统一改名为“干系人”；项目与干系人为多对多，项目表单用**可搜索的多选 Combobox** 选择干系人。干系人支持公司和多个联系方式；角色属于“项目—干系人”关联，按项目填写，同一干系人在不同项目可以有不同的角色。下文作为“需求提出方/确认方”的业务角色仍可称客户。

## 1. 信息架构

### 1.1 主导航

```
工作台
项目
干系人
设置
```

**为什么没有全局"需求 / 变更 / 版本"页**：排期和需求管理都按项目组织，避免同一份数据出现两套入口。跨项目查找靠 `Ctrl+K` 全局搜索和工作台上的汇总卡片。

以后如果需要"跨项目需求总表"，再加一个全局"需求"页，放 P1。

### 1.2 项目内导航

```
项目详情
├─ 概览
├─ 需求
├─ 沟通
├─ 版本与排期
├─ 变更
└─ 活动
```

### 1.3 页面跳转关系

```
工作台 ──→ 项目概览 ──→ 需求详情 ──→ 变更详情
   │            │            │
   │            ├─→ 沟通记录（抽屉）
   │            ├─→ 版本与排期
   │            └─→ 变更列表
   └─→ 干系人 / 项目列表
```

**卡片行为**：

| 区域 | 内容 | 点击后 |
| --- | --- | --- |
| 待确认需求 | 所有项目中状态为草稿/澄清中的需求数 | 打开抽屉，列出需求，点击进入详情 |
| 待处理变更 | 草稿/评估中/待确认的变更单数 | 打开抽屉，列出变更，点击进入详情 |

| 最近动态 | 状态变化、变更应用、沟通新增 | 直达对应实体 |

工作台不提供排期操作；"未排期"事项点击后进入对应项目的"版本与排期"页。

### 3.3 原始需求（合同范围）

入口：项目详情 → 原始需求 → 导入 Excel。

导入流程：

1. 选择 `.xlsx / .xls / .ods` 文件，选择工作表；
2. 设置起始行，并映射模块列、子项列、描述列；
3. 预览识别出的模块和子项，填写来源文件标题和版本；
4. 导入后原始需求锁定，保留 Excel 行号，不直接进入开发状态。

没有 Excel 时，可以直接“新建原始需求”，填写模块、标题和描述；手工录入的条目归入“手工录入原始需求”来源文件，不影响已导入的 Excel 基线。

列表按模块分组，每条显示编号、原始描述、源行号和覆盖状态：

- **未细化**：还没有关联开发需求；
- **已细化 N**：已关联 N 条开发需求，展示开发需求编号和状态。

操作：

- **新建沟通记录**：打开沟通记录表单，自动关联当前原始需求；
- **细化**：打开开发需求表单，来源固定为“原始需求”，自动关联当前原始需求，并预填标题和描述；
- 点击标题查看完整原始描述和已关联的开发需求。

一个项目可以导入多份来源文件；列表默认显示最新一份，也可以切换到“全部来源文件”。

## 4. 需求台账

```
┌────────────────────────────────────────────────────────────────────────────┐
│ 需求                                      ＋ 新建需求   ⋯ 批量粘贴        │
│ 筛选：状态 ▾  类型 ▾  优先级 ▾  版本 ▾  来源 ▾   [未排期]  搜索…         │
├──────┬──────────────────────┬──────┬──────┬────────┬──────┬──────┬───────┤
│ 编号  │ 标题                  │ 类型 │优先级│ 状态    │ 版本 │ 开发  │ 完成  │
├──────┼──────────────────────┼──────┼──────┼────────┼──────┼──────┼───────┤
│ ▾001 │ 客户数据导入          │ 功能 │ 高   │ 已排期  │ V1.0 │ 10/22│ 10/28 │
│  002 │ 　导入模板下载        │ 功能 │ 中   │ 开发中  │ V1.0 │ 10/23│ —     │
│  003 │ 　字段映射配置        │ 功能 │ 中   │ 已确认  │ —    │ —    │ —     │
│ 004  │ 权限管理              │ 功能 │ 高   │ 澄清中  │ —    │ —    │ —     │
│ 005  │ 操作日志              │ 非功能│ 低  │ 草稿    │ —    │ —    │ —     │
└──────┴──────────────────────┴──────┴──────┴────────┴──────┴──────┴───────┘
```

**列**：

- 默认显示：编号、标题、来源、状态、版本、优先级、开发开始、完成、更新时间。
- 可开启：类型、提出方、预估、创建时间。
- 来源分为：原始需求、沟通记录、直接创建；原始需求来源必须关联原始需求，沟通记录来源必须关联沟通记录。
- 标题列带层级缩进和展开箭头；父需求显示子需求数量。
- 状态、优先级、版本支持行内修改。

**筛选**：

- 状态、类型、优先级、版本（含"未排期"）、来源；
- 开发开始/完成时间范围；
- 关键词（编号、标题、描述）。

**快速操作**：

- 行首勾选 → 批量：分配版本、改状态、取消需求、删除草稿；
- 行内按钮：开始开发、完成；
- 顶部输入框直接新增：标题 + 类型 + 优先级，回车保存。

**批量粘贴**：弹窗粘贴多行文本，每行一条草稿需求；预览后批量保存。

**空状态**：没有需求时显示"从粘贴客户需求列表开始"，引导批量录入。

## 5. 需求详情

```
┌──────────────────────────────────────────────────────────────────────┐
│ CRM-012  会员数据导出          [已排期] [高]  V1.0  10/20–11/10     │
│ 实际开发：10/22 – 10/28（历时 7 天）   预估：3 人天                  │
│ [编辑] [开始开发] [完成] [拆分] [更多 ▾]                             │
├──────────────────────────────────────────┬───────────────────────────┤
│ 描述                                     │ 类型      功能            │
│ ……                                       │ 来源      客户            │
│                                          │ 所属版本  V1.0            │
│ 验收标准                                 │ 父需求    —               │
│ 1. 支持导出 CSV                          │ 子需求    2 条            │
│ 2. 支持选择字段                          │ 创建      10/12 14:20     │
│                                          │ 确认      10/15 10:00     │
│ 设计说明                                 │ 开发开始  10/22（自动）   │
│ ……                                       │ 完成      10/28（自动）   │
│                                          │                           │
│ 设计链接  Figma ↗   技术方案 ↗           │ 附件（2）                 │
├──────────────────────────────────────────┴───────────────────────────┤
│ 版本历史 | 沟通（3） | 变更（1） | 附件（2） | 时间线                 │
├──────────────────────────────────────────────────────────────────────┤
│ 版本历史：                                                           │
│ v3  10/20  缩减范围  删除"导出 Excel"要求      变更：CRM-CR-003      │
│ v2  10/15  细化验收标准                                             │
│ v1  10/12  创建                                                     │
│ [对比 v1 与 v3]                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

**操作**：

| 操作 | 行为 |
| --- | --- |
| 编辑 | 修改标题、描述、验收标准、设计说明、类型、来源、优先级、预估 |
| 开始开发 | 状态改为"开发中"；首次记录实际开始日期 |
| 完成 | 状态改为"已完成"；记录实际完成日期；未开始则自动补开始日期 |
| 拆分 | 输入子需求标题，生成子需求；父需求变为汇总节点；子需求继承版本 |
| 更多 → 取消需求 | 必须填写原因；状态改为"已取消"，保留历史 |
| 更多 → 移动版本 | 选择新版本；记录归属变化 |
| 更多 → 发起变更 | 打开变更向导，预填当前需求 |
| 添加沟通 | 打开沟通抽屉，自动关联当前需求 |
| 附件 | 上传多个文件；图片预览；其他文件用系统程序打开 |

**版本历史**：每次内容保存生成一个版本；可以任选两个版本对比，差异用增删标记展示。

**时间线**：创建、澄清、确认、排期、开发开始、完成、取消、版本变更、日期手改，全部按时间倒序。

**子需求区域**：父需求详情页下方列出子需求，显示各自的编号、标题、状态、版本、实际开发日期；可展开进入子需求详情。

```
│                               │ 实际：10/22 ~ 10/28（进行中）            │
│ [ ] CRM-004 权限管理   高     │ ┌──────┬────────────┬──────┬──────┐     │
│ [ ] CRM-005 操作日志   低     │ │编号  │标题         │状态  │开发  │     │
│ [ ] CRM-008 消息通知   中     │ │001  │客户数据导入 │已完成│10/28 │     │
│ ...                           │ │002  │导入模板下载 │开发中│—     │     │
│                               │ └──────┴────────────┴──────┴──────┘     │
│ 已选 2 条                     │                                          │
│ [分配到版本 ▾] [取消选择]     │ V1.1  2026-11-15 ~ 2026-12-10  [规划中] │

```

**左侧待排期池**：

- 只显示未分配版本、且状态为"已确认/设计中"的需求；
- 可按优先级、类型筛选；
- 支持多选和全选。

**右侧版本列**：

- 版本名、起止日期、状态；
- 需求数量、预估总工时、完成数/总数；
- 实际开发区间：该版本需求的最早开始 ~ 最晚完成；
- 需求列表：编号、标题、状态、预估、实际开发日期；
- 版本操作：编辑日期/目标、归档。

**操作**：

- 勾选需求 → "分配到版本" → 选择版本；需求状态自动变为"已排期"；
- 版本内需求可"移出"回待排期池（状态回到"已确认"）；
- 需求可在版本间移动；已发布版本移入/移出需填写原因（P1 可加锁定）；
- 版本没有起止日期时，显示提示"未设置日期"；
- MVP 不做拖拽，全部用勾选 + 按钮。

**客户视图**：切换后隐藏内部备注、成本、风险、内部字段，只保留变更标题、原因、影响范围/工期、变更项的前后差异、确认记录和附件。页面按 A4 宽度排版，方便截图或打印。

**新建变更向导**：

1. **基本信息**：标题、原因、提出人、提出日期；
2. **变更项**：添加现有需求（修改/缩减范围/取消）、新增需求（填写新需求内容）、拆分/合并（P1）；
3. **影响与确认**：范围影响、工期影响、费用（可选）、影响版本、风险、确认渠道/时间/人/备注、附件。

**应用变更**：

- 展示受影响需求和新旧差异的预览；
- 确认后在一个事务里：更新需求内容、生成新版本、创建新增需求、更新状态/版本、写入活动记录；
- 应用后变更单锁定，不能直接修改；需要再发一次变更。

**变更状态**：草稿 → 待确认 → 已确认 → 已生效；任一未生效状态可取消。客户不同意时取消并填写原因。

## 8. 沟通记录

沟通记录使用**独立整页编辑器**，不使用会被点击遮罩关闭的弹框；适合长会议、跨天续谈和大量附件。

```
┌────────────────────────────────────────────────────────────────────┐
│ ← 返回沟通记录   数据同步范围确认             [进行中]  已自动保存 │
│                                       [完成记录] [归档] [新建需求] │
├────────────────────────────────────────────────────────────────────┤
│ 涉及原始需求 [SRC-01-01-01 ×]   关联开发需求 [CRM-012 ×]          │
│ 主题附件 [上传]  会议纪要.pdf                                      │
├───────────────────┬────────────────────────────────────────────────┤
│ 沟通场次           │ 第 2 场：10/22 微信                            │

```

- **自动保存**：输入停止约 700ms 自动保存；显示“保存中 / 已自动保存 / 保存失败”，失败时可重试。
- **场次**：跨天没聊完时新增场次，默认今天日期，继承上一场的参与人和渠道；上一场内容保留。
- **完成/重新打开**：完成记录只改状态，不关闭页面；以后可重新打开继续补充。
- **归档**：归档代替物理删除，默认列表隐藏，可恢复。
- **附件**：支持多选上传、Ctrl+V 粘贴微信截图、拖拽文件；图片显示缩略图并可预览，其他文件调用系统程序打开；移除附件为软删除。
- **离开保护**：返回项目或关闭窗口前会先保存；保存失败时阻止离开并提示。

项目内的“沟通记录”标签页展示主题列表，显示状态、场次数、附件数、最近场次和关联需求，可按状态筛选和搜索主题/场次内容。

## 9. 附件

- 需求、沟通记录、变更单都支持多附件；
- 上传时复制到应用数据目录 `attachments/<project_id>/<communication_id>/`，不依赖原文件路径；
- 图片内联预览；PDF/Office/压缩包调用系统程序打开；
- 单文件上限 50MB；不限制类型；
- 删除附件需确认；
- 每日备份包含数据库和附件目录；
- 导出 JSON 时包含附件元数据；完整打包导出（含文件）放 P1。
